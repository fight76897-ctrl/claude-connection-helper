# Claude 连接助手

Windows x64 本地应用，为 Claude 网页版、Claude Desktop、Claude Code、Claude Science 桌面版和选定 API 程序配置同一条代理链路，并提供按程序路径的出站阻断。

```text
专用浏览器 / Desktop / Code / Science / 已配置代理的 API 程序
                              ↓
                 助手 127.0.0.1:17861
                              ↓
               本地 VPN 127.0.0.1:15236
                              ↓
                    你的美国静态住宅代理
                              ↓
                          目标服务
```

启动时必须核对预期静态出口 IP 和美国归属；通过前拒绝业务流量。之后持续检测，失败会关闭助手代理和已有隧道，不自动回退直连。Windows 防火墙规则独立保留，ProxyBridge 可补充所选程序的路由和回环阻断。

**首次使用需在本机填写住宅代理参数、启用保护并验收客户端请求。固定出口不能保证账号不会被封禁。**

## 打开应用

从仓库 Releases 下载 `ClaudeConnectionHelper-0.2.1-Setup-x64.exe`，按向导安装。安装器会创建桌面和开始菜单快捷方式；支持 Windows x64。安装包未做代码签名。

安装到新位置后，助手自身的程序路径会改变，请重新核对并应用保护规则。卸载前如需恢复普通联网，请先停止连接、停止 ProxyBridge，再运行“恢复直连”；卸载器会保留用户配置和防火墙规则。

打开发行目录中的 `ClaudeConnectionHelper.exe`，保留整个目录。源码打包后的默认位置为 `dist/ClaudeConnectionHelper-win32-x64/ClaudeConnectionHelper.exe`。

## 第一次配置

1. **连接本地 VPN。** 默认示例 HTTP 入口为 `127.0.0.1:15236`，请按自己的 VPN / 本地代理设置填写。
2. **填写美国住宅代理。** 先按服务商给这个端口标注的协议选择 **HTTP CONNECT** 或 **SOCKS5**。地址只填域名或 IP，不带协议、路径或端口；端口另填。用户名、密码直接在本机界面填写。旧配置默认保持 HTTP CONNECT；若端口实际为 SOCKS5，请切换后保存。仅接受 TLS 的 HTTPS 代理端口暂不支持。
3. **填写预期静态出口 IP，必填。** 应填写服务商提供的实际出口 IP，可能与代理服务器地址不同。
4. 点击 **“保存配置” → “启动连接”**。助手通过上述两级代理查询 `api.country.is`；只有 IP 与预期一致且国家为 `US` 才放行业务连接。查询失败、超时或不一致都会停止代理。
5. 在 **“直连阻断”** 中核对并勾选实际使用的程序路径，点击 **“启用所选保护”**，完成确认及 Windows 管理员授权。启动入口会检查对应程序是否已有有效防火墙规则。
6. 从 **“开始使用”** 打开客户端。使用期间保持本地 VPN 和助手运行。需要 ProxyBridge 时，再按下文启动拦截。

每次成功检测后约 **30 秒**再检查，单次查询超时为 **25 秒**；也可点击“检测出口”立即检查。两次检测之间存在变化未被发现的时间，检测不能证明每条客户端请求都从美国发出，也不认证 IP 的住宅属性。

住宅用户名、密码通过当前 Windows 账户加密保存。代理地址、预期 IP 和手动选择的程序路径保存在当前用户的应用数据目录。连接记录包含目标、时间、进程及路由状态，不记录请求正文、代理认证头或 Claude 登录令牌。

## 四个入口

| 入口 | 使用方式 |
| --- | --- |
| Claude 网页版 | 内置专用浏览器使用独立 Cookie、固定代理，禁用 QUIC 并限制 WebRTC 非代理 UDP。它没有伪造指纹功能。 |
| Claude Desktop | 完全退出已运行的客户端，再从助手启动。助手传入固定代理参数和代理环境变量；可手动选择安装位置。 |
| Claude Code | 选择项目目录后启动。代理环境变量和本次启动的 Code 设置指向助手。npm 安装版可能共用 `node.exe`，应核对实际运行时路径。 |
| Claude Science 桌面版 | 保存研究任务，从系统托盘完全退出后再从助手启动，使代理环境变量生效；可手动选择安装位置。 |

助手不会强制结束正在运行的 Desktop 或 Science。支持发现 Claude Desktop 的 MSIX 安装；实际启动与登录仍需本机验收。

授权页若打开普通浏览器，请复制链接到专用浏览器菜单 **“导航 → 粘贴并打开登录链接”**。普通浏览器不自动纳入保护。Desktop 登录回调仅从受信任的 Claude / Anthropic HTTPS 页面交给通过助手启动的客户端，回调内容不写入日志。Science 可使用 **“Paste code instead”**，在专用浏览器完成授权后粘贴完整代码。

内置浏览器的真实登录流程尚未验证，第三方登录服务可能限制嵌入式浏览器。

## 自动追踪客户端更新

助手启动时和运行期间每 **60 秒**扫描已安装客户端及相关程序路径，包括 Desktop MSIX 安装位置、Science 版本目录和当前发现的子进程。也可点击“重新扫描”。

界面显示 Desktop 和 Science 的可执行文件版本；扫描时读取本地版本元数据，变化会写入记录。Science 运行时的版本元数据可能对应 Electron，不等同于产品版本。

- 新路径会加入候选列表并提示，旧路径和既有保护规则保留。请核对新路径、勾选并重新启用保护；未补齐规则时，对应入口会拒绝启动。
- ProxyBridge 已运行时，需停止并重新启动拦截，将新增路径写入专用配置。新路径在规则更新前不属于其拦截范围。
- 手动指定安装位置后，该位置优先；软件迁移到别处时需重新选择。

这里追踪的是本机已安装版本和程序位置，不会自动下载、安装或替客户端升级，也不保证预先发现所有未来子进程。客户端自行更新并启动的新路径，在补齐规则前可能不受保护。

## ProxyBridge 程序路由与观察

集成对象为 [InterceptSuite/ProxyBridge](https://github.com/InterceptSuite/ProxyBridge)，当前按 **4.2.0** 配置格式接入。使用上方保护列表中勾选的客户端；助手自身不加入 ProxyBridge 规则，以免拦截上游链路。

1. 确认美国出口检测通过，并已为所选程序启用防火墙保护。
2. 点击 **“生成配置”** 可导出独立的 `claude-helper.pbprofile`，不会覆盖已有 `Default` 配置，也不会启动拦截。
3. 点击 **“启动拦截与记录”**，核对程序范围并完成管理员授权。已有连接需自行退出客户端后重启，建议继续从助手入口启动，让客户端明确使用代理。

专用规则按顺序阻断所选程序的 UDP、阻断其他本机回环连接，再把 TCP 送入助手端口。回环阻断也可能影响 MCP、本机工具和登录回调；共享 Node / Python 会影响其他使用相同运行时的任务。

**透明转发与当前 Windows 防火墙规则的兼容性尚未实机验证。** 防火墙可能先拒绝透明连接，导致不能联网。客户端支持时应保留显式代理配置；不要把“ProxyBridge 进程已启动”视为路由成功。

连接记录用于观察进程、目标、端口及代理／直连／阻断尝试，不代表请求已成功或出口已验证。它不会把观察结果自动加入允许规则，不读取请求正文来“学习”流量。

ProxyBridge 停止或异常退出后，其 UDP 和其他回环阻断会失效；助手检测到异常会关闭自己的代理。独立防火墙规则仍阻断受保护程序的非回环出站，但保留所有回环连接，因此无法在 ProxyBridge 退出后继续禁止程序改用其他本机代理。

## 添加其他 API 程序

1. 在工具支持的代理设置中填写 `http://127.0.0.1:17861`。支持环境变量时可设置 `HTTP_PROXY`、`HTTPS_PROXY` 为此地址，将 `NO_PROXY` 限定为 `localhost,127.0.0.1,::1`。
2. 点击 **“添加 API 程序”**，选择真正发起请求的 `.exe`，重新启用所选保护。脚本通常需要选择实际使用的 `node.exe` 或 `python.exe`。
3. 如需 ProxyBridge，将新路径加入其专用规则并重新启动拦截。工具不支持显式代理时，当前防火墙可能使其无法联网，需单独验收。

## 保护范围

- 防火墙按完整 `.exe` 路径阻断非回环 IPv4、IPv6 和 UDP 出站，影响该路径的所有进程。它不会自动识别系统里所有“与 Claude 有关”的请求。
- 未选中的程序、新安装路径、尚未发现的子进程和由其他服务代发的流量不在相同路径规则内。系统 DNS 服务可能代发 DNS 请求，不能据此宣称 DNS 已全部进入住宅代理。
- 防火墙保留回环通信，规则在助手退出后继续生效；只有运行中的 ProxyBridge 专用规则补充限制其他本机代理。内置浏览器使用自身固定代理设置。
- 出口检测验证的是助手到查询服务的链路和该服务返回的国家信息，不能替代各客户端真实请求的验证。
- 防火墙服务及相关配置必须启用。无法确认规则有效时，界面会显示异常或未受保护，启动入口会拒绝放行。

## 停止与恢复网络

**“停止连接”** 会停止本地代理并断开已有隧道，保留运行中的 ProxyBridge 和防火墙保护。**“停止拦截”** 会同时关闭助手代理和本助手启动的 ProxyBridge。正常退出助手也会停止这两者，防火墙规则继续保留。

如需恢复普通联网：

1. 先停止连接及 ProxyBridge 拦截，再点击 **“恢复直连”**，确认并完成管理员授权。
2. 助手打不开时，运行发行目录的 **`restore-network.cmd`**。它只移除规则组 `ClaudeConnectionHelper.OutboundGuard.v1`，不关闭系统防火墙或修改其他软件规则；它不会代替停止 ProxyBridge。
3. 将经助手启动的客户端或 API 程序完全退出后正常打开，清除该次启动继承的代理设置。内置浏览器仍固定使用助手代理。

源码恢复脚本为 `scripts/restore-network.ps1`。移动或删除应用目录前，按需要先恢复直连。助手只停止自己启动的 ProxyBridge 会话，不接管其他已有实例。

## 常见情况

| 现象 | 处理 |
| --- | --- |
| 端口 `17861` 被占用 | 关闭另一份助手或占用该端口的程序后重试。 |
| 无法连接本地 VPN | 确认 Veee 正在运行，HTTP 地址和端口正确。 |
| 住宅代理返回 `407` | 核对用户名、密码和 HTTP 端口。 |
| 住宅代理在建立隧道前关闭连接 | 核对住宅代理协议是否与端口一致；SOCKS5 端口需选择 SOCKS5。 |
| SOCKS5 认证失败 | 核对服务商提供的用户名、密码及 IP 白名单设置。 |
| 出口 IP 不符、不是美国或检测超时 | 助手已关闭连接；先核对线路及服务商提供的出口信息，再重新启动。 |
| Desktop / Science 已在运行 | 保存任务，从托盘完整退出，再从助手启动。 |
| 更新后显示未保护 | 核对新路径并应用保护；ProxyBridge 同时需要重启拦截。 |
| 启用保护后不能联网 | 核对客户端显式代理和运行时路径；透明转发可能被防火墙拒绝。按需使用恢复步骤。 |
| 本机 MCP / 工具连接失败 | 检查 ProxyBridge 回环阻断影响范围，按需停止拦截并重新核对所选程序。 |

## 开发与验证

```powershell
npm install
node node_modules/electron/install.js
npm test
npm start
npm run package
npm run installer
```

当前验证范围与待验收项目见 [验证说明](docs/validation.md)。0.2.1 已使用本机保存的参数，通过本地 VPN → SOCKS5 住宅代理完成一次真实出口检测，IP 与预期一致且国家为 US。四个入口的登录与请求，以及 ProxyBridge 和真实防火墙共同运行的效果仍需端到端验收。开发验证没有更改系统代理，也没有结束用户已有客户端或研究任务。
